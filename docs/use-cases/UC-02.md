# UC-02 · Crear los proyectos `core/` + `backend/`

| Campo | Valor |
|---|---|
| **Fase** | 0 — Preparación del entorno |
| **Tipo** | Desarrollo |
| **Actor** | Equipo de desarrollo |

## Descripción

Crear la librería compartida `Niuro.Core` (`core/`, classlib con dominio, aplicación e infraestructura compartida) y el proyecto ASP.NET Core Web API `Niuro.Api` (`backend/`). `backend/` es el punto de entrada HTTP del formulario: recibe la solicitud, corre el rule engine y persiste transaccionalmente. El resto de proyectos se crean en sus propios UCs (UC-03 a UC-05).

El API se configura con **Serilog** (logging a archivo). Junto con el worker (UC-03), ambos escriben en el mismo archivo rolling diario `logs/niuro-backend-YYYYMMDD.log` (carpeta `logs/` en la raíz del repo); el template del output incluye la propiedad **`Service`** (del `LogContext`) para diferenciar cada proceso. El mock (servicio de terceros) no loguea a este archivo.

`Niuro.Core` es un classlib y **no** lleva Serilog: el logging vive en los entry points (`Niuro.Api`, `Niuro.Worker`).

**Estándar de nombres**: cada proyecto se llama `Niuro.{Proyecto}` (`Niuro.Core`, `Niuro.Api`).

## Precondiciones

- `UC-01` completado (la solución `NiuroTest.slnx` existe).

## Flujo principal

1. Ejecutar `dotnet new classlib -n Niuro.Core -o core` y agregar a la solución: `dotnet sln add core/Niuro.Core.csproj`.
2. Ejecutar `dotnet new webapi --use-controllers -n Niuro.Api -o backend` (o el template equivalente). Dependiendo de la plantilla de .NET 10, podría ser Minimal API + controllers; el resultado debe ser un API Web.
3. Agregar referencia al proyecto compartido: `dotnet add backend/Niuro.Api.csproj reference core/Niuro.Core.csproj`.
4. Agregar a la solución: `dotnet sln add backend/Niuro.Api.csproj`.
5. **Instalar Serilog en el API** y agregar las versiones al `Directory.Packages.props` (paso 2 de UC-01): `Serilog.AspNetCore` y `Serilog.Sinks.File`.
6. **Configurar Serilog en `Program.cs`** de `Niuro.Api`:
   - Sink `File` apuntando a `logs/niuro-backend-YYYYMMDD.log` (ruta compartida con el worker, rolling diario).
   - `LogContext.PushProperty("Service", "Niuro.Api")` para identificar cada entrada (el mock no escribe aquí).
   - Template de output que incluya `{Service}`.
7. Verificar compilación: `dotnet build`.

## Excepciones

- Versión del template distinta a la esperada → adaptar el comando y documentarlo en el README.

## Postcondiciones

- `core/` (`Niuro.Core`) y `backend/` (`Niuro.Api`) en la solución y compilando.
- `backend/` depende de `core/` (nunca al revés); `core/` no referencia a ningún proyecto.
- `Niuro.Api` inicia con **Serilog** logueando a `logs/niuro-backend-YYYYMMDD.log` con la propiedad `Service = "Niuro.Api"`.
- `backend/` listo para recibir el endpoint del UC-07.
