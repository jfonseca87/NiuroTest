# UC-03 · Crear el proyecto Worker Service `worker/`

| Campo | Valor |
|---|---|
| **Fase** | 0 — Preparación del entorno |
| **Tipo** | Desarrollo |
| **Actor** | Equipo de desarrollo |

## Descripción

Crear el proyecto `Niuro.Worker` (plantilla `worker`) en `worker/`. Es un **proceso aparte** (`BackgroundService`) que lee la tabla `OutboxEvents` y envía los eventos al Servicio Externo por HTTP. Vive separado del API por rendimiento y aislamiento: el worker puede escalar, reinstalarse o detenerse de forma independiente sin afectar el endpoint del formulario.

El worker se configura con **Serilog** (logging a archivo). Junto con el API (UC-02), escribe en el mismo archivo rolling diario `logs/niuro-backend-YYYYMMDD.log` (carpeta `logs/` en la raíz del repo); el template del output incluye la propiedad **`Service`** (del `LogContext`) para diferenciar cada proceso. El mock (servicio de terceros) no loguea a este archivo.

**Estándar de nombres**: cada proyecto se llama `Niuro.{Proyecto}` (`Niuro.Worker`).

## Precondiciones

- `UC-02` completado (existe la solución con `core/` y `backend/`).

## Flujo principal

1. Ejecutar `dotnet new worker -n Niuro.Worker -o worker`.
2. Agregar referencia al proyecto compartido: `dotnet add worker/Niuro.Worker.csproj reference core/Niuro.Core.csproj`.
3. Agregar a la solución: `dotnet sln add worker/Niuro.Worker.csproj`.
4. **Instalar Serilog en el worker** y agregar las versiones al `Directory.Packages.props` (paso 2 de UC-01): `Serilog.Extensions.Hosting` y `Serilog.Sinks.File`.
5. **Configurar Serilog al arrancar el host** (`Program.cs` del worker):
   - Sink `File` apuntando a `logs/niuro-backend-YYYYMMDD.log` (misma ruta que el API, rolling diario).
   - `LogContext.PushProperty("Service", "Niuro.Worker")` para identificar cada entrada (el mock no escribe aquí).
   - Template de output que incluya `{Service}`.
6. Verificar compilación: `dotnet build`.

## Excepciones

- Sin dependencia de `backend/`: el worker NO referencia al API (si llegara a necesitarlo, es señal de que el código está en el proyecto equivocado).
- **Si este UC requiere modificar o agregar algo en `core/`** (dominio, aplicación o infraestructura compartida), se hace también aquí: `worker → core` y `backend → core` comparten esa librería, y cualquier ajuste queda cubierto por este UC (y por UC-02 para el side del API).

## Postcondiciones

- `worker/` (`Niuro.Worker`) compila como proceso independiente y depende solo de `core/`.
- `Niuro.Worker` inicia con **Serilog** logueando al mismo archivo que el API (`logs/niuro-backend-YYYYMMDD.log`) con la propiedad `Service = "Niuro.Worker"`.
- Preparado para implementar el polling del outbox del UC-13.
