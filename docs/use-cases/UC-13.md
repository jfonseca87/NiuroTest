# UC-13 · Publicar y procesar el evento en background

| Campo | Valor |
|---|---|
| **Fase** | 4 — Evento en background al servicio externo |
| **Tipo** | Negocio |
| **Actor** | Sistema NiuroTest (Worker Service, proceso aparte) |

## Actores y proyectos involucrados

- `worker/` (`Niuro.Worker`): **proceso aparte** (`BackgroundService`) que sondea la BD.
- BD PostgreSQL: tabla `OutboxEvents` (escrita en UC-11/12).
- `core/` (`Niuro.Core`): `NiuroDbContext` + `OutboxEvent` entity + `MockExternalClient` (typed HttpClient, infraestructura) reusados por el worker.
- `mock/` (`Niuro.Mock`): destino del envío HTTP (UC-14).

## Descripción

Después del commit (UC-11/12), el **Worker Service** lee los `OutboxEvents` **pendientes** y envía el payload al Servicio Externo por HTTP — **fuera del request** que respondió el formulario. Cliente nuevo → `POST` (create); cliente que regresa → `PUT` (update).

## Contrato técnico (worker → mock)

```
POST http://localhost:5200/api/customers           # Operation = Create (SSN va en el body)
PUT  http://localhost:5200/api/customers/{ssn}     # Operation = Update
Content-Type: application/json
Acepta 200 OK del mock.
```

**Payload del evento** (`OutboxEvent.Payload`), mismo shape para ambas operaciones:
```json
{
  "customer": { "firstName": "John", "lastName": "Doe", "address": { "street": "123 Main St", "city": "Buffalo", "state": "NY", "zipCode": "14201" }, "companyName": "ACME Inc", "ssn": "123-45-6789" },
  "application": { "id": "0198-...", "requestedAmount": 25000.00 }
}
```

## Flujo principal (Worker Service)

1. `OutboxWorker.ExecuteAsync`: loop con intervalo fijo (p. ej. 5 s) + `CancellationToken`.
2. Cada ciclo: consulta `OutboxEvents` con `Status = Pending` (`AsNoTracking`, orden por `CreatedAt`, límite razonable).
3. Para cada evento:
   - `Operation = Create` → `POST /api/customers` con el payload completo.
   - `Operation = Update` → `PUT /api/customers/{ssn}` (el SSN se extrae del payload/evento).
   - Éxito (`200`) → evento `Status = Sent` (+ `ProcessedAt`). `SaveChangesAsync`.
   - Excepción → evento `Status = Failed` (+ `Error` con el mensaje), log en Serilog (`Service=Niuro.Worker`). **Sin reintentos** (decisión de simplicidad, documentada en ARCHITECTURE.md).

## Excepciones

- **Fallo de envío HTTP (no del commit)**: los registros de customer/application YA están commiteados — **no** se hace rollback. El evento queda `Failed` para inspección. Rollback ante fallo de envío y "procesado en background" son mutuamente excluyentes.
- **Worker caído/BD caída**: los `Pending` quedan pendientes; al volver el worker, se procesan (en última instancia el outbox es la fuente de verdad de lo no enviado).
- **Sin reintentos por defecto**: un intento por evento; si falla, `Failed` con el error. (Si en una iteración futura se decide reintentar, documentarse y justificarse en ARCHITECTURE.md; no usar Polly salvo decisión explícita.)

## Implementación técnica

- `worker/Program.cs`: host con Serilog (UC-03) + DI: `AddDbContext`, `AddHttpClient<MockExternalClient>(ExternalService:BaseUrl)` (IHttpClientFactory, nunca `new HttpClient()`), `AddHostedService<OutboxWorker>()`.
- Configuración por `IOptions<T>`: `ConnectionStrings:Postgres` y `ExternalService:BaseUrl` (apunta a `http://localhost:5200`), validada al arrancar con `OptionsBuilder.Validate`.
- **Lifetimes**: `DbContext` scoped (el worker crea scope por ciclo o por evento); `BackgroundService` singleton → usa `IServiceScopeFactory` (nunca inyecta scoped directo: captive dependency).

## Postcondiciones

- El evento se envía al Servicio Externo y queda `Sent` o `Failed`.
- El usuario recibió su decisión (UC-11/12) sin esperar este proceso.
