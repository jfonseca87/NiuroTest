# UC-09 · Denegar por estado NY

| Campo | Valor |
|---|---|
| **Fase** | 2 — Denegación |
| **Tipo** | Negocio |
| **Actor** | Sistema NiuroTest · Solicitante |

## Actores y proyectos involucrados

- `core/` (`Niuro.Core`): la regla `StateNyRule` del engine (UC-08).
- `backend/` (`Niuro.Api`): traduce el `Result` a HTTP.
- `frontend/`: página de denied con el motivo.

> La regla `NY` es UNA regla más del engine (UC-08). Agregarla/quitarla no modifica las demás ni el `RuleEngine`.

## Descripción

Si `State = NY` → la solicitud es denegada. Se muestra al solicitante la página de **denied** con el motivo.

## Contrato técnico (backend → frontend)

El API responde dentro del `POST /api/loan-applications` del UC-07:

```
200 OK
{ "status": "denied", "reason": "STATE_NY", "applicationId": null }
```

**NO es un error HTTP**: es un `200` con `status: denied` (Result Pattern). El estado se normaliza a **mayúsculas** antes de comparar.

## Precondiciones

- El payload pasó la validación de entrada (UC-07).

## Flujo principal

1. Normalizar `state` a mayúsculas (`ny` → `NY`).
2. `RuleEngine.EvaluateAsync` aplica `StateNyRule`: `state == "NY"` → aplica.
3. El engine devuelve `Result` `Failure` con `ReasonCode = "STATE_NY"`.
4. El controller responde `200` con `{ status: "denied", reason: "STATE_NY" }`.
5. El frontend muestra la página de denied con el mensaje legible ("No se puede procesar solicitudes desde NY").

## Excepciones

- Estado ausente en payload → ya rechazado por validación (400/422) en UC-07; la regla solo evalúa datos válidos.

## Postcondiciones

- La solicitud queda denegada. **No se persiste nada** (ni Customer ni Application) y **no se publica ningún evento** al servicio externo (no hay outbox).
